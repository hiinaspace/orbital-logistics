## Implemented behavior

- Ship/body selection, future path hover, click to pin/place a maneuver, and
  click-to-engage radial/transverse handles. Move without holding; click to
  commit, Escape or another control to cancel. A gesture is one undo operation.
- Separate immutable reference, draft, accepted program and execution runner.
  Amber draft paths become dashed while updating; only the current, converged
  prediction with valid snap provenance can execute.
- Precision components/reference/epoch, signed increments, up to eight authored
  nodes, previous/next/delete, undo/redo, and named-body apsis occurrence snaps.
  Saved semantic windows detect stale, missing or ambiguous snaps. Upstream
  edits never silently move a snapped burn; re-snap or explicitly keep its epoch.
- Nonrotating inertial, body-centered and accepted-execution-ship frames. Each
  path sample subtracts its origin at that sample's epoch. Frame and camera
  changes do not rewrite burn components.
- Preview scrub independent of committed execution; pause/play, warp, reset and
  advance; JSON save/load/download retains baseline, draft, accepted plan,
  preview epoch and replay-validated execution snapshot. M0 saves still import.
- Compact UI with operational labels; removed the M0 footer and explanatory
  subtitles. Precision, encounter values, JSON and debug state are collapsible.

The opening two-body goal is apoapsis radius 1.4–1.6. The retained moon fixture's
goal is surface altitude 0.065–0.075 during t=2.4–2.6 (center distance 0.09–0.10).
These are local normalized fixture quantities, not an authored campaign.

## Dynamics and calibration

Prediction and execution use `Runner` and the same fuel-accounted impulse
implementation. Event diagnostics refine radial-speed roots from canonical safe
coast brackets, with pre-impulse endpoints. A velocity jump is not an apsis;
near-circular coasts have no unique occurrence. Closest distance, surface
altitude, epoch and body-relative speed use the refined coast event or endpoint.
The existing conservative unsupported-approach policy remains in force; impact
time is not refined and unresolved paths cannot execute.

Every fresh UI prediction compares h and h/2 positions, velocities, event epochs
and event/terminal classifications. Disagreement of 1e-5 or more, classification
changes or a failed refinement blocks execution. This is an additional runtime
check, alongside independent offline calibration, rather than a general error bound.

`npm run evidence:m1` retains **83 cases**, each at h=1/512, 1/1024 and 1/2048:
27 tutorial cases and 54 binary cases cover component corners/zero, three epochs
and both available reference bodies. Two authored goal-reaching plans are added.
77 cases reach the horizon; six consistently stop as unsupported approaches.
Independent SciPy DOP853 uses separate NumPy force/ephemeris code, actual surface
events, tightened-tolerance comparison, refined apsides and impulse/fuel checks.

Acceptance is 1e-5 for each quantity. The positional threshold is 1% of a 0.001
encounter-distance resolution and 0.05 pixels at 5000 pixels/unit, below the
plan's 0.25-pixel close-up target. Even at the maximum 10000 pixels/unit camera
scale, the largest observed oracle error is about 0.0023 pixels. These checks
cover a sampled bounded domain, not every continuous component value or
multi-node queue. The runtime refinement check and surface guard cover new
drafts conservatively; neither proves arbitrary close-pass validity.

The user accepted the important CoaDE UI behaviors and inertial frame switching,
requested visual apsis placement and coarse node-time editing, and authorized
proceeding on 2026-10-06. This passes the manual-editor gate by user approval;

body when viewing a body frame, otherwise the selected burn's reference or the

previewed epoch. Circular coasts still have no invented apsis. Clicking within
