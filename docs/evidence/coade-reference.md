## 2D adaptation for the first slice

Borrow the sequence, not the mission content. Begin with a compact overview the player can pan/zoom and recenter; let them select one ship and inspect its orbit and remaining Δv. A single “plan trajectory” action should make the selected object's forecast visually distinct from its current/reference orbit. Let pointer position along the forecast preview time, and let a click pin a maneuver epoch. Keep the authored path visible against its baseline while the player adjusts two in-plane handles: radial toward/away from a named body and tangential along the documented local orbital direction.

Preserve the tutorial's distinction between hovering over a forecast to inspect future state and clicking the path to pin the maneuver epoch. The installed tutorial says the tangential handle can be moved without holding the mouse, so do not assume a conventional pointer-down drag. First observe how the original handle is activated, adjusted, committed, and cancelled; then choose a small, explicit interaction state machine that preserves the feeling of direct manipulation. Make the path itself carry the first explanation: show the changed shape, a small burn mark, and a direct before/after preview as the handle changes. Put exact epoch, signed component values, total Δv, and Δv cost in a compact inspector on selection or explicit expand; don't make numeric entry the first interaction. Keep the burn list visible enough to undo, select, and clear an edit. Numbers should confirm what the picture already communicates and remain available for deliberate precision.

Teach frame selection by letting the player switch between inertial overview and a named-body-centered, nonrotating view while retaining the same maneuver and physical forecast. The path should visibly move relative to the centered body while its forecast in the inertial view remains unchanged. Treat the manual-editor portion as the M1 stopping point. The source tutorial continues with orbit matching, orbit phasing, rendezvous/join, cargo refueling, and a return trip; deliberately defer those synchronization and logistics interactions to later milestones (orbit matching/phase/join first fit M2). Do not include cargo or multi-ship synchronization in this opening interaction.

A lightweight tutorial can use contextual prompts attached to the relevant control, but should allow exploration: point at pan/zoom/recenter, selection, forecast scrub, pin epoch, activate and adjust one handle using the gesture chosen after live observation, undo/inspect values, switch frame, then ask the player to explain the visual change. Keep guidance short and dismissible; don't reproduce the game's dialogue, artwork, colors, icons, or assets. Test the visual-first/numbers-on-demand choice with the player before adding more guidance or helper automation.
