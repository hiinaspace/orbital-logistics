## Shared model and time contract

- `src/sim/` imports no DOM, canvas, worker or clock. Its public input/output is
  structured-cloneable data. `fixtures/m0-circular.json` records all units, physical
  surfaces, masses, integration policy and schema/model versions.
- RK4 uses the scenario-epoch grid with h=1/512 in the supplied fixtures.
  Explicit burn epochs split grid intervals. Bodies use fixed or analytic circular
  inertial rails. Gravity is unsoftened; ships have no gravitational backreaction.
- Burn vectors use pre-burn position relative to their saved reference body.
  Transverse is the CCW perpendicular to radial, including on clockwise/eccentric
  paths. This is not a velocity-aligned basis. No camera input enters dynamics.
- Ideal impulse fuel is `mass * -expm1(-deltaV / exhaustVelocity)`, using current
  dry+cargo+propellant mass. Unaffordable burns leave velocity/fuel/cursor unchanged
  and terminate the forecast. Duplicate epochs are rejected on input. An initial
  surface collision precedes a coincident burn.
- The runner computes complete canonical intervals on demand, sometimes looking
  ahead of the requested playback epoch. This is a cache, not early execution:
  returned fuel/cursor/ledger reflect only the requested epoch. Partial display
  queries propagate from the preceding node and never become integration origins.
  Deterministic safety subdivisions also ignore request partitions.
- Seek selects a retained checkpoint and propagates forward; it never integrates
  backward. Reset reuses immutable history. Separate prediction and execution
  runners use the same implementation. Rendered paths are decimated views.
- Snapshots retain the canonical anchor, next grid index, burn cursor, ledger,
  status and requested epoch. A partial requested endpoint is not an anchor.
  M0 reload validates snapshots by replay from the saved scenario/program; it
  does not yet use untrusted snapshots to accelerate a fresh run. Object-key order
  is immaterial. Negative zero is normalized at schema input for JSON stability.

## Surface protection and bounded domain

For each coast interval, the core bounds ship/source displacement and acceleration
within each body's half-clearance neighborhood. A sufficient bound certifies
that all RK4 stages and the continuous coast stay outside every physical surface.
Uncertified intervals are halved deterministically, up to the saved subdivision
limit. Surfaces on moving rails include the source's maximum speed in the bound.

An initial on/inside-surface state is `collision`. An approaching path that cannot
be certified terminates at its last safe state as `unsupported-approach`; this
does **not** claim a refined impact epoch or prove that every such path collides.
There is no singularity traversal, softened gravity, surface teleport or free
capture. The policy intentionally rejects some feasible close passes. M1 needs
its actual reachable edit domain calibrated; refined collision/apsis/encounter
locators remain unimplemented.

Input validation limits scenarios to 8 sources, 128 ordered unique burns,
duration ≤64, h≥1/65536, ≤65536 retained nodes, subdivision depth ≤20, and 256000
characters per imported JSON. Scenario duration must be an integral number of
grid steps. Arbitrary *requested* preview horizons can end between grid nodes
and extend later without changing the future. Changing scenario duration/model
is a new validated run, not mutation of an old checkpoint. Node-budget exhaustion
terminates explicitly as `work-limit`; retention cannot grow without bound.
Validation also checks finite numeric fields, schema/model versions, IDs,
positive physical parameters, mass/capacity and burn references.

## Measured calibration

`npm run evidence:m0` regenerates `m0-numerics.json`, `m0-oracle-input.json` and
`m0-oracle-report.json`. The raw request is retained here as durable evidence,
not browser runtime data. The original planning samples/reports remain untouched.

Independent Kepler equations check 601 epochs for circular, e=0.6 eccentric,
and e=1.5 hyperbolic motion. The eccentric test checks apsides and a complete
period. Maximum state errors at h=1/512:

| Calibration | Horizon | Maximum state error |
| --- | --- | --- |
| Circular | 2π | 3.03e-12 |
| Eccentric e=0.6 | 2π | 6.14e-9 |
| Hyperbolic e=1.5 | 4 | 1.74e-10 |

Step halving from 1/128 → 1/256 → 1/512 reduces state error by approximately
16× per refinement. Energy/angular-momentum drift is retained in the raw report.
An additional independent Kepler ellipse check covers the prepared browser burn
through t=16 with state disagreement <1e-9.

The retained planning encounter's initial state seeds `fixtures/m0-binary.json`.
Production fixed/circular ephemerides, with and without a radial/transverse burn,
are compared to a separately implemented NumPy/SciPy DOP853 oracle. The new burn
components (0.015, -0.01) are in the named local basis; they are not the old spike's
inertial components. Across 601 epochs to t=6, h=1/512 maximum position error is
2.47e-10 (coast) and 1.03e-10 (impulse). Maximum state error is 2.68e-10.
Tightening DOP853 changes its state by <3.5e-12. Fuel accounting also agrees.
These are bounded-fixture results, not long-horizon/general close-pass evidence.
