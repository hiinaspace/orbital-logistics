# Initial M2 rendezvous — 2026-10-06

The user accepted M1's important CoaDE UI behaviors and inertial frame switching,
requested two spatial editing refinements and authorized proceeding. Those
refinements are retained in `93b5cbe` and [M1 evidence](m1.md). This checkpoint
implements the planned bounded M2 slice. M3 docking/logistics is not implemented;
the new proposal interaction is ready for user review.

## Playable slice

Choose **Rendezvous**, select the departure maneuver, optionally revise its
components, and click **Target**. A purple proposed trajectory and meeting marker
appear at the fixed arrival epoch, beside the current draft and target. The panel
shows departure/arrival Δv, total/change in cost, fuel and residual miss.

**Reject** preserves the draft. **Accept** replaces the departure components and
adds an explicit arrival burn in one undoable draft change. It does not execute
the plan. **Execute plan** accepts and runs that draft through the same `Runner`.
The two fuel-consuming impulses appear in the execution ledger. Preview and
execution times remain separate, and a new nonrotating target-centered frame uses
the target's integrated state at each trajectory sample's epoch.

The target is a massless coasting spacecraft, propagated with the shared dynamics,
not an extra gravitational source or a teleporting port. Initial state, target,
times, branch, component bounds and tolerances persist in versioned scenario JSON.

## Solver domain and failure behavior

The authored fixture uses a fixed primary with μ=1 and surface radius 0.08, an
initial circular ship orbit of radius 1, and a circular target orbit of radius 1.4.
Departure is fixed at t=0.5 and arrival at t=4.629730790872742; horizon is t=6.
The target phase was authored from an analytic half-ellipse transfer, giving an
independent known solution. This is a local targeting experiment, not route search.

- Exactly one selected departure burn, at the named epoch and reference body.
  Snapped departures and additional queue nodes are outside this first helper.
- Radial component in [-0.12, 0.12], transverse in [-0.05, 0.2].
- CCW angular momentum, angular sweep strictly between 0 and 2π, and minimum
  surface clearance 0.5. Every propagated finite-difference and line-search trial
  checks the same branch/clearance and fuel constraints. Bounds failures are
  rejected before propagation. The helper never changes target, epochs or branch.
- Central finite differences at ±1e-4 (one-sided where a trial is invalid), a
  2×2 Newton update, correction trust radius 0.04 and up to eight halving attempts.
  At most 12 iterations and 96 trial evaluations; no alternate starting seeds.
- Solve position residual below min(position tolerance/100, 1e-7), then compute
  the full arrival velocity-matching impulse in the saved radial/transverse basis.
  Forward-run both burns through the horizon. Insufficient fuel, unsafe paths,
  singular sensitivities, no improvement or exhausted work return a failure.
- Position and speed tolerances are both 1e-4. h/h2 checks of the ship and target
  at 81 common epochs plus both burn epochs must disagree by less than 1% of
  the respective tolerance, with complete trajectories at both steps. The usual
  prediction refinement and event-classification gate also applies to the proposal.

Worker cancellation terminates actual work. Edits, scene/load changes and explicit
Cancel invalidate the generation and terminate the solver worker; completed
results must match revision/scenario/model/horizon. Pending, failed, cancelled and
rejected solves do not mutate draft or accepted execution. A valid proposal must
be explicitly accepted before its burns enter the draft. Save/replay preserves
authored burns, not an invisible runtime correction policy.

This does not claim arbitrary multi-body targeting, long horizons, multiple
revolutions or robust convergence throughout all imported scenarios. The branch
and numerical evidence apply to this bounded fixed-primary experiment. No docking,
attachment, cargo or free capture is performed.

## Numerical evidence

`npm run evidence:m2` solves three manually chosen seeds, retains every trial and
the resulting programs, and propagates each proposal at h=1/512, 1/1024 and 1/2048.
SciPy DOP853 independently propagates ship and target, with tightened tolerances,
actual surface events, independently calculated impulse axes and fuel accounting.
An analytic Hohmann check additionally validates both impulse magnitudes and fuel.

| Seed (radial, transverse) | Initial miss | Iterations / evaluations | Added total Δv |
| --- | ---: | ---: | ---: |
| Closer (0, 0.078) | 0.029524 | 2 / 11 | 0.075761 |
| Initial (0.015, 0.065) | 0.155596 | 3 / 16 | 0.087053 |
| Worse (0.05, 0.02) | 0.691083 | 5 / 26 | 0.099909 |

All three converge to total Δv ≈0.153761: departure ≈0.08012345 and arrival
≈0.07363750. Propellant used is ≈0.08993221. The saved initial-seed solution has
independent arrival miss 9.37e-11 and relative speed 8.90e-13; the largest miss
among the three seeds is 4.16e-8. Across all samples/steps, maximum production vs
oracle position error is 2.18e-12 and velocity error 1.14e-12, well below 1e-6
(1% of capture tolerance). Target state disagreement is below 3.01e-13. These
are normalized units and sampled checks, not universal error bounds.

## Application verification

Build/typecheck, **45 headless tests** and **10 production Chrome browser tests**
pass, with no page or console errors. The added checks cover analytic matching,
both impulse costs, closer/worse seeds, branch/revolution/clearance rejection,
insufficient arrival fuel, bounded work, unsupported queues/epochs, coarse
accuracy rejection, proposal isolation/undo, preserved target metadata, save/load,
real cancellation and stale-result rejection. The original M0/M1 checks remain.
Python Ruff format/lint and ty checks pass through the configured hooks.

`node scripts/m2-browser-evidence.mjs` records a separate headless Chrome against
the built review preview. Initial/worse/closer solves took 859/366/229 ms from
external click dispatch to visible proposal, including protocol, worker startup,
solve/verification/transfer and DOM scheduling. These are three individual runs
on natto, Chrome 154.0.8037.97, 1440×1000 viewport with recording, not a latency
distribution. The first run overlapped the final headless test suite, so these
are observed application timings under that load rather than an isolated benchmark.
