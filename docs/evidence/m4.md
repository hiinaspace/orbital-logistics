# M4a: fixed-program return puzzles — 2026-10-06

The user accepted M2 refinements/M3a, requested cleaner execution viewing, and
explicitly chose to proceed into puzzles with absolute maneuvers before dynamic
route intent. This implements that **initial M4a slice**. M3b's second ship/joint
handoff is deferred by this sequencing decision; it is not implemented. The full
M4 gravity-assist/hardware/synchronization and human optimization gates remain open.

## Play

Refresh `http://127.0.0.1:4178/`. The scenario menu now separates Puzzles and Sandbox.

1. **Return ticket:** the provided outbound program loads 0.2 at Home, delivers it
   to Depot and draws 0.1 fuel. Author the return; arrive empty with ≥0.05 fuel.
2. **Express return:** same task and equipment, but return by **t=18.25**.

In Rendezvous, choose the target port and explicit departure/arrival epochs.
**Place departure** creates a zero-impulse node, which can also be placed spatially
or edited with the existing precision controls. Select that node and **Target**.
The proposal lists its departure/arrival burns and newly added Undock/Dock actions.
**Accept** changes the draft as one undoable action; **Execute plan** is separate.
The starter has no return answer button. Default epochs provide a gentle first
return; the timed variant requires another window. Earlier cargo/service actions
remain editable, with normal physics/resource failures.

**New attempt** restores the starter and retains saved solutions. Existing legs
are literal burns and port events: retiming one burn does not silently move its
other operations. Use New attempt for a fresh return window, or edit the queue's
related absolute epochs explicitly. This is a current authoring limitation to
assess in the human optimization session, not runtime adaptation.

Successful actual executions save nondominated solutions locally. The table
separates completion time, gross consumed propellant and declared hardware cost.
It does not collapse them into one score. Refueling is not a negative fuel cost.
The forecast marked **Plan** does not earn a solution; the entire accepted program
must execute to its valid horizon. A later failed operation disqualifies it.
**Replay** runs a saved program through the same Runner; the download button exports
its exact scenario/program JSON, reloadable through Save/load. Storage failures
leave session records usable and visibly indicate session-only saving.

Fixed puzzle identity compares every validated scenario field, including physics,
inventories, equipment, tolerances, objective and deadline. Altering these in an
import opens a sandbox rather than crediting the original puzzle. Records retain the exact scenario as well as the program, so changed puzzle rules
make an old record ineligible. Stored score numbers are untrusted and recomputed by bounded replay of the stored programs.
At most 12 nondominated records per puzzle are retained. Hardware is fixed at one
tug in these two scenes; hardware optimization is not demonstrated yet.

The express program finishes 1.626757 earlier and consumes about 71% more fuel.
Only it satisfies Express return's deadline. Both still deliver 0.2 net cargo,
end empty/docked at Home, and debit the Depot's 0.1 refuel stock. M4's explicit

These are authored feasibility witnesses, not claims of globally optimal routes
or player-discovered solutions. A browser-authored third route (15.5→19.5) uses
0.13219091, giving the same visible tradeoff against the express route.

## Targeting and viewing contract

The existing fixed-primary shooter now accepts an explicit target port/time.
It preserves the player's epochs and earlier program; no window/route search.
Trials use the actual cargo/fuel/service prefix, with a CCW coast of <1 revolution,
minimum surface clearance 0.2, departure components in [-0.25,0.25], at most 12
Newton iterations / 96 evaluations. An intervening burn or operation blocks the
single-coast solve. Pending service, failed prefix, unaffordable arrival, invalid
arrival, branch/bounds/work failure or unresolved refinement leave the input
unchanged. A port's target coast is calibrated against its analytic circular rail;
final docking checks the actual rail and fully charges its bounded velocity residue.
New Undock/Dock actions are proposed visibly, not applied on arrival as free capture.
Arrival-burn provenance remains static authoring metadata, with no runtime solve.
Proposal fuel uses the gross ledger rather than initial-minus-final tank contents.
Worker generation/revision checks and cancellation also cover changed port/time.

**Layers** independently toggles Plan (including reference/proposal), Orbits,
Markers and Trail. **Bodies only** toggles all four off and restores the previous
combination on a second click. Invisible nodes/apsides/encounters/paths have no hit
regions; physical objects remain selectable. Hidden markers also remove grid,
labels and selection/preview annotations. Scrubbing still shows synchronized bodies.

Followed plan segments become thin translucent grey only through the identical
accepted/draft event prefix; an edited hypothetical past never gets that treatment.
The cyan executed trail ends at the real execution epoch, not a future scrub time,
and its alpha decreases with age (0.90 at the tip, approaching 0.08). It uses the
accepted Runner's sampled path plus the exact live endpoint. Every frame transform
uses each sample's own epoch. View changes do not revise or advance the live Runner.
The desktop inspector scrolls separately to keep playback near the viewport.
