# Maintained service follow-up — 2026-10-09

The user reported long Tern waits, expensive close returns and playback hitches.
This pass diagnoses the schedule and improves disposable display processing.
It does **not** change admitted physical programs, timing, station controllers,
fuel budgets or numerical policy. No new outside review ran this pass.

## Reproduction and evidence

All runs use the checked-in `orison-maintained-service.json` on natto. The baseline
is commit `37bb8cf`. The [1536-unit rollout](rollout-before.json) advanced in unit
requests with 24-step work budgets, ingested incremental display deltas, and
recorded every visit, failure and 32-unit station phase/fuel sample. Run:

```
ROLLOUT_OUTPUT=docs/design/maintained-service/follow-up/rollout-current.json node --import tsx docs/design/maintained-service/follow-up/rollout.ts
PROFILE_OUTPUT=docs/design/maintained-service/follow-up/profile-current.json npx playwright test tests/browser/maintained-profile.spec.ts
node --import tsx docs/design/maintained-service/follow-up/probe.ts
```

The profiler uses its own headless installed Chrome, development server4179,
main-thread CDP CPU samples and Long Task/heap observers. It leaves the user's
4178 preview/tab alone. The diagnostic is opt-in and skipped by the normal suite.
The probe is a retained experiment, **not** a runtime planner or certified set.
Its duplicated planner is deliberately scoped to the fixed baseline for auditing
this experiment; it is not a second production implementation to maintain.

## What explains the traffic

The 1536-unit run completed17 returns, without a runtime/storage exception.
It recorded108 failed dispatches:51 maintenance-envelope failures,44 force-bound
failures,9 unsupported approaches and4 lack-of-improvement failures. Long home
waits after refueling were120 units before departure382,160 before774, and512
before1438. The first pair at30 consumed.444396 fuel (rocket-equation delta-v
.775907) and reached radius1.130238; the starting orbit is radius2 and Orison's
radius is1. This is genuinely an expensive close pass, not a drawing-frame effect.

Three constraints interact:

1. Dispatch tests only departure `controlEpoch+6` on an8-unit control grid.
   Fixed14-unit legs and2-unit dwells make the usual repeat departure40 units
   apart, versus ideal relative-orbit recurrence39.000972. These gradually sample
   different geometry; the same cadence cannot keep favorable phasing forever.
2. Both legs must solve together, using one zero-revolution prograde Lambert seed
   per leg, two fixed-force pulses and a bounded Newton search. The first feasible
   paid pair is admitted; there is no delta-v objective, branch comparison or
   arrival-time search. A failed seed/Newton solve does **not** prove the transfer
   physically impossible. In particular, the current componentwise force bound
   is an inscribed cube, stricter and axis dependent relative to the engine's
   physical force sphere. This deserves correction/calibration in the planner
   slice rather than interpreting all44 failures as true hardware limits.
3. Meridian's finite stationkeeping tank is unreplenished. The first controller
   failures appear by800, and fuel reaches.100938 (just above.1 reserve). The
   station then coasts between occasional admissible corrections and often falls
   outside the dispatch envelope. This explains much of the *later* waiting, not
   the initial long gaps.

Meridian's angular error against its nominal clock is−.002886 radians at256 and
−.007612 at512, about−.17° and−.44°. At1536 it is−.556539, about−31.9°, after
fuel limitations. Early skipping is therefore not primarily uncontrolled phase
migration. Phase control is physically plausible: [ESA describes east-west
stationkeeping](https://www.esa.int/Enabling_Support/Space_Engineering_Technology/Running_on_empty).
Keeping each station near its own nominal phase would still preserve different
Keplerian angular rates at radii2 and3, and therefore transfer windows.

An independent **ideal two-body calculation**, ignoring perturbations and finite
burn duration, gives Hohmann half-transfer12.418235, economical relay dwell
23.496429 and round-trip delta-v.256885. Current dwell2 forces a return before
that alignment. [NASA's return-transfer explanation](https://pwg.gsfc.nasa.gov/stargaze/Smars3.htm)
describes the same wait-versus-energy tradeoff; it is archival teaching material.
These analytical values are design diagnostics, not admitted finite-force routes.

## Bounded alternative probe

[probe.json](probe.json), generated by [probe.ts](probe.ts) and
[probe-planner.ts](probe-planner.ts), tests20 independent departures6..158 spaced8
apart against the same canonical station stream. Each pair uses outbound14,
relay dwell2, return38 and home dwell2. The return is seeded from a tangent
Hohmann-like ellipse intended to take an extra revolution; all executed burns
are still finite forces. Admission still checks both paid captures, reserve,
clearance and every canonical owner/provider lease sample.

Four candidates succeeded (6,46,86,126): delta-v.464–.509, minimum radius
1.764–2.002, maximum radius3.098–3.200. The other16 failed within the same
per-leg96-evaluation bound. Compared with the baseline first trip, this is a
less expensive and less extreme family, but **not** proof of regular service:
these are independent tests, not one fueled sequential dispatch rollout, and
longer trips cannot cover all of those departure windows with one ship. No
independent DOP853/convergence certificate was run for this exploratory family.
Do not ship it merely because it improves a few witnesses.

Recommended next architecture slice: separate outbound and return decisions;
search bounded departure/arrival intervals and let Tern dwell at Meridian until
an economical return. Rank feasible candidates by paid propellant and wait/time
tradeoffs, with an explicit outer evaluation budget; correct the axis-dependent
search bound and compare appropriate branches before expanding solver freedom.
Long relay dwell crosses stationkeeping burns and needs a physical owner for the
attached ship/station aggregate mass and fuel accounting. The same ownership
work then permits explicit station refueling. Maintain existing immutable
admitted-target leases, event-side captures, worker yielding and bounded history.
Astra should review that ownership/scheduling proposal before implementation.
Phase locking alone is not the recommended next fix.

## Display changes and measured result

The solver was already off the main thread. Main-thread load came from repeated
history merges, rebuilding predictions on a second shifted sampling grid,
cloning identical drawing queries and exact sphere clipping for segments that
missed all projected bodies. The shipped changes:

- Reuse immutable chunk/visit payloads and cached merged station drawing streams.
- Reuse admitted dense prediction/event samples instead of creating another grid.
- Cache up to256 drawing queries per disposable vessel descriptor in a WeakMap.
- Batch scene/chart/timeline refreshes at the existing100ms panel cadence, skip
  refresh for solver replies with an unchanged head, and refresh synchronously
  on Pause so its pose stays exact across pending acknowledgement.
- Fast-path clipping when a segment misses all projected sphere bounding boxes;
  intersecting segments still use the original analytic occlusion geometry.

Profiles [before](profile-before.json), [intermediate](profile-after.json) and
[final](profile-final.json) cover about47 seconds of the same16× default-view
playback, ending at heads524.93,530.27 and518.66 respectively. The files retain
30 hottest sampled frames, not complete CPU traces. Final versus baseline:

| Measurement | Before | Final |
|---|---:|---:|
| `visibleSegment` sampled self time | 4.840s | .939s |
| `worldPath` sampled self time | 2.221s | .670s |
| history `view` sampled self time | 1.028s | .159s |
| main-thread idle sampled time | 6.959s | 27.805s |
| observed peak main JS heap | 103.07MB | 61.35MB |
| observed Long Tasks | one99ms | one91ms |

There was no observed unbounded retained-history growth or recurring >50ms task
storm. The baseline still spent much of the interval busy, consistent with
jitter below the Long Task threshold. Heap includes transient allocation and GC
sampling, and this is one host/browser sample, not a frame-rate guarantee.
The intermediate cache-only run peaked159MB; eliminating duplicated prediction
sampling and throttling descriptor reconstruction was material. Physical worker
cost can still slow simulated progress while it solves. The measurements do not
claim all playback hitches are eliminated.
